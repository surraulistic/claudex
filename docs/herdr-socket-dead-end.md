# Сокет herdr вместо подпроцессов — измеренный тупик

11.09.2026. Проверялось: перевести обращения claudex к herdr с запуска бинаря
на unix-сокет `~/.config/herdr/herdr.sock`.

## Что обещало выигрыш

Сокет существует и полон: 77 методов, включая `agent.list/get/read/wait/prompt`,
`events.subscribe`, `events.wait`. Всё это уже в 0.8.2 — в 0.9.0 ничего из этого
не добавилось. Первый замер из python дал 2.9 мс на запрос против 11.3 мс на
запуск `herdr`, то есть вчетверо дешевле.

## Почему не вышло

Из node тот же самый запрос стоит ~110 мс.

    connect   0.2-0.5 мс      ← соединение мгновенно
    ответ     105-117 мс      ← и один прогон из восьми: 3.0 мс

Не помогли: `setNoDelay`, сырые буферы вместо `setEncoding`, запись до события
`connect`. Минимум 4.3 мс доказывает, что сервер отвечает быстро, но
воспроизвести это из node стабильно не удалось.

Дополнительно: сервер закрывает соединение после каждого ответа (второй запрос
в том же сокете даёт BrokenPipe), поэтому переиспользовать соединение нельзя —
батчинг отпадает вместе с ним.

## Итог

    подпроцесс herdr   11.3 мс/вызов
    сокет из node     ~110   мс/вызов     в 10 раз хуже

Замер из python не переносится на нашу среду выполнения. Транспорт остаётся
подпроцессным. Возвращаться к этому имеет смысл, только если найдётся причина
задержки на стороне node.
