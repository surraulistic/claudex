# claudex

Одна короткая сводка по сессиям Claude Code вместо шести ручных вызовов.
Склеивает проиндексированную историю с живым состоянием из Herdr.

## Установка

```bash
./install.sh
```

Собирает бинарь, кладёт его в `~/.local/bin` и линкует скилл в
`$CODEX_HOME/skills` (по умолчанию `~/.codex/skills`). Для сборки нужен `go`,
для работы — `herdr` и `cass` в `PATH`. Sqlite встроен, отдельного `sqlite3`
не требуется.

## Откуда берётся история

`cass` читает сессии Claude Code, Codex, Cursor и Gemini в свою базу, а
`claudex index` собирает из неё локальный индекс с FTS5:

```bash
cass index --full      # разовый полный проход по исходникам
claudex index          # догнать индекс (--full — пересобрать)
```

Поиск идёт по FTS5 SQLite, поэтому работает на любом языке. Собственный
`cass search` кириллицу не индексирует — им не пользуемся.

Если Codex не подхватит скилл по симлинку, скопируйте каталог:
`cp -R skills/claudex ~/.codex/skills/claudex`.

## Скилл для Codex

`skills/claudex/SKILL.md` — обычный скилл Codex в каноне
`~/.codex/skills/.system/skill-creator`. Проверка:

```bash
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py skills/claudex
```

Отдельный плагин не заводился: плагин в Codex — это связка скиллов, hooks, MCP
и запись в `config.toml` (как `casino-toolkit`), а здесь одна возможность.
Если понадобится собрать всё в плагин, каталог `skills/claudex` кладётся в его
`skills/` без изменений — раскладка та же.

## Адресация

Цель — метка вкладки (то, как панель подписана в Herdr), алиас, `pane_id`,
`session_id`, `transcript_id`, кусок заголовка или cwd. У каждой панели в
`sessions` есть поле `target`, которое гарантированно работает.

```bash
claudex install             # по метке вкладки — обычный способ
claudex wE:p13              # по панели
```

Алиас — необязательное удобство, живёт он в самом Herdr и снимается, когда агент
в панели выходит или заменяется новым:

```bash
herdr agent rename wE:pB river
```

## Команды

```bash
claudex brief                             # все живые панели разом — основной вход
claudex sessions                          # легче: кто жив и у кого есть история
claudex wE:p13                            # полный дайджест одной панели
claudex river --limit 12 --chars 600      # глубже
claudex river --pretty                    # с отступами, для глаз
claudex search wE:p9 "MessageWhiz"        # поиск внутри одной сессии
claudex find "river миграция"             # поиск по всем транскриптам
claudex find "wallet currency" --days 14  # то же, но не старше двух недель
claudex watch install                     # ждать освобождения панели и выйти
claudex delegate install "<задача>"       # поручить и дождаться (ход занят)
claudex delegate install "<з>" --detach --notify codex   # не занимая ход
claudex entry <entry-id>                  # запись целиком, без обрезки
claudex context <entry-id> --before 4     # разговор вокруг записи
```

`entry` и `context` читают индекс напрямую и ничего не обрезают.

Прямой `herdr agent prompt` отправляет задачу и на этом всё: никто не ждёт
завершения, Codex не просыпается, в логе пусто. Привязать наблюдателя задним
числом нельзя — ожидание должно начинаться вместе с отправкой. Поэтому единый
путь один: `claudex delegate` (или обёртка `tools/delegate-and-monitor.zsh`).
Панель со статусом `working` и `watched: false` в `sessions` — это и есть след
прямого вызова.

`--detach` отдаёт наблюдение отдельному процессу и возвращает управление за
доли секунды: ход вызывающего не занят, с ним можно продолжать разговор.
Хвостовой `&` этого не даёт — дочерний процесс наследует stdout, пайп остаётся
открытым, и оболочка всё равно ждёт EOF (замерено: двухсекундный фоновый `sleep`
задержал вызов на 2021 мс). Оторванный наблюдатель ведёт свою группу процессов,
переживает вызывающего и присылает результат уведомлением, поэтому `--detach`
требует `--notify`.

`delegate` отказывается отправлять в панель со статусом не `idle` и не `done`
(код выхода 6): herdr поставил бы промпт в очередь и перемешал две задачи.
Отдельной фазы взведения нет — отправка и ожидание уходят одним вызовом
`agent.prompt{wait}`, и щели между ними, в которую проваливался быстрый
ответ, не остаётся.

`watch` блокируется, пока панель занята, и завершается, когда она освободилась.
Модель при этом не работает и токены не тратятся: ожидание живёт внутри herdr,
который и так отслеживает состояние панелей — ни хука, ни опроса. Запускать
фоном: харнесс разбудит агента на завершении процесса, а в выводе уже будет
дайджест панели. Код выхода 5 — не дождался; JSON при этом не печатается
вовсе, и состояние панели остаётся неизвестным, а не `idle`.

`brief` укладывает все панели в один процесс: хвосты читаются параллельно, а
обращения к индексу идут разом. Семь отдельных дайджестов стоят впятеро дороже
той же картины. Хвост запрашивается не длиннее высоты панели — за этой границей
herdr восстанавливает прокрутку, и десять панелей вместо 3 мс стоят секунду.

`find` ходит по всем транскриптам, включая давно закрытые сессии, и сворачивает
попадания в сессии: у каждой проект, каталог, ветка, число хитов и окно
активности. Ключ `target` у группы можно сразу передать в `claudex <target>` —
в том числе когда `provider_session_id` пуст и адресовать приходится по
`transcript_id`. Слова объединяются через AND, хвостовая `*` даёт префикс,
`--raw` пропускает синтаксис FTS5 как есть.

Живое управление сюда не входит — это сам Herdr, по тому же имени:

```bash
herdr agent read river
herdr agent prompt river "продолжай Payment" --wait --until idle
herdr agent wait river --until idle --timeout 600000
```

## Что на выходе

```json
{
  "target": "river",
  "alias": "river",
  "live": { "pane_id": "wE:pB", "session_id": "…", "status": "working",
            "title": "…", "cwd": "…", "focused": false },
  "history": { "transcript_id": "…", "entry_count": 11900,
               "last_activity": "…", "entries": [ { "id": "…", "ts": "…",
               "role": "assistant", "text": "…", "chars": 3924, "truncated": true } ] },
  "tail": ["⏺ …"],
  "signals": { "mr": [], "tickets": [], "repo": null,
               "last_user_prompt": "…", "current_tool_call": null }
}
```

`signals` — только проверяемые извлечения. Смысловые выводы делает читатель.

`entry_count` равен `null`, а не `0`, когда историю прочитать не удалось: ноль
читался бы как «в сессии тихо».

У каждой записи есть `id`: если `truncated` и это важно, полный текст берётся
через `claudex entry <id>`, окружение — через `claudex context <id>`.

`tail` читается при любом статусе, но источник выбирается по состоянию панели:
у работающей `--source recent` отдаёт пусто, поэтому берётся экран; у покоящейся
`recent` приносит вчетверо больше строк.

`context_pct` и `limits` берутся из статусной строки: насколько заполнен контекст
панели и близки ли лимиты. Панель под 100% контекста вот-вот уйдёт в компакт —
новую задачу ей давать нельзя.

Сигналы с узкой панели намеренно скупые. Ужатая статусная строка режет id и в
середине списка — `SD-6613` приезжает как `SD-66`, которого не существует, —
поэтому такие строки пропускаются целиком. Пустой `mr` означает «на экране нет
ничего проверяемого», а не «нет MR».

`history` может прийти с полем `reason` вместо `entries` — обычно потому, что
сессия началась после последнего прохода индекса. Это лучше, чем показать ноль
записей и сделать вид, что в сессии тихо.

`entry_count` считает только разговор: примерно семь записей из десяти — это
заглушки `[Tool: …]`, они остаются в поиске, но не в ленте. А `last_activity`
учитывает любую запись: панель, которая час гоняет инструменты, не простаивает.

## Коды выхода

`0` успех, в том числе с деградировавшей историей · `2` цель не найдена или
неоднозначна · `3` Herdr недоступен · `4` ошибка вызова · `5` не дождался ·
`6` панель занята, задание не отправлено · `7` сбой herdr при ожидании — исход
неизвестен. Читать `7` как `5` нельзя: «не смогли узнать» — не «не завершилось».

## Скрипты

```
tools/delegate-and-monitor.zsh   единый путь: отправить, дождаться, разбудить Codex
tools/herdr-guard.zsh            необязательный перехват прямых herdr agent prompt
```

`delegate-and-monitor.zsh` — обёртка над `claudex delegate` с логом и расшифровкой
кода выхода. Постоянного процесса не заводит: наблюдатель живёт одну задачу.

```bash
CODEX_TARGET="codex install" tools/delegate-and-monitor.zsh install "<задача>"
```

`herdr-guard.zsh` по умолчанию **не установлен**. Он отклоняет прямой
`herdr agent prompt` — тот отправляет задачу, но никто не ждёт её завершения.
Включение и обход описаны в шапке файла.
